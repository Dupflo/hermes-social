# Campaign Rules Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Replace the single `.env` keyword/resource setup with a scalable campaign/rules system supporting multiple videos/posts, keywords, public replies, and DM messages.

**Architecture:** Keep `.env` only for secrets and deployment settings. Move business content into SQLite tables: campaigns/rules identify platform + post/media scope + keyword(s) + messages. Webhook processing loads the matching rule for each comment and executes the configured response. Add simple CLI/admin commands first; a small Hermes/HTTP admin UI can come later.

**Tech Stack:** FastAPI, SQLite, pytest, existing Meta Graph client.

---

## Current context

- Current config in `app/config.py` has one global `RESOURCE_KEYWORD`, `RESOURCE_URL`, and `PUBLIC_REPLY_TEXT`.
- `app/processor.py` receives a `CommentEvent`, checks one keyword, then replies with one hard-coded resource URL.
- `app/store.py` currently stores only processed comments.
- This does not scale to several reels/videos/posts with different keywords and messages.

## Proposed model

Create a new SQLite-backed rules table, stored in the existing database file:

```text
campaign_rules
- id INTEGER PRIMARY KEY
- name TEXT NOT NULL
- platform TEXT NOT NULL              # instagram | facebook | any
- media_id TEXT                       # specific IG media/post id, optional
- post_id TEXT                        # FB post id, optional
- keyword TEXT NOT NULL               # e.g. proxy
- public_reply_text TEXT NOT NULL
- dm_text TEXT NOT NULL               # full DM text, can include the URL
- enabled INTEGER NOT NULL DEFAULT 1
- created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
- updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
```

Matching order:

1. enabled only;
2. platform exact or `any`;
3. if `media_id`/`post_id` is set, it must match the event media/post id;
4. keyword must match comment text;
5. prefer the most specific rule over global fallback:
   - exact media/post rule first;
   - then platform-level rule;
   - then `any` rule.

## Future admin options

After CLI works, choose one:

1. **Hermes-operated CLI only** — fastest and enough for now. You tell Hermes “ajoute une règle pour cette vidéo”, Hermes runs the CLI.
2. **FastAPI admin endpoints** — e.g. `POST /admin/rules`, protected by an admin token.
3. **Small admin UI** — later, once rules stabilize.
4. **Notion/Airtable as source of truth** — possible, but avoid now because webhooks should stay fast and reliable.

Recommended now: **SQLite + CLI + Hermes commands**.

## Risks / tradeoffs

- Need reliable media/post IDs. We may need helper CLI commands to list recent IG media and FB posts.
- Meta webhook payload may provide `media_id` for Instagram and `post_id` for Facebook differently; tests should cover both.
- If several rules match the same comment, specificity and priority must be deterministic.
- Avoid exposing secrets in any admin route; business content is not secret, tokens stay in `.env`.

## Open questions

- Do you want matching scoped per exact video/post, or should one keyword apply globally across all posts?
- Should one comment trigger several resources if it contains several keywords, or only the first/best rule?
- Do you want the DM text to be full custom text per rule, or a template plus URL?
